# Практика 6. Моделирование угроз и атаки с помощью LLM

## На занятии

### Часть занятия с преподом

Препод рассказывает что ориентир — [моделирование угроз Microsoft](https://learn.microsoft.com/en-us/azure/security/develop/threat-modeling-tool-getting-started): описание системы, поиск угроз, меры защиты и проверка. На занятии строим эту модель в markdown и/или mermaid.live

Препод рисует модно стильно молодёжно вместе с аудиторией какой-нибудь сервис с AI интеграцией и симулирует вектора атаки: ПДн, 152-ФЗ, prompt injections, llm as judge и прочие приколы

### Часть занятия в группах

Затем препод раскидывает аудиторию по группам по 4 человека и говорит придумать свой сценарий и нарисовать самим схемку в любой рисовалке.
Например можно рассмотреть: покупка мебели в магазине типа IKEA, просмотр погоды, бронирование столика, заказ доставки.

### Часть занятия с демо

Команда отдает решение преподу, препод запускает решение у LLM и пытается сказать саммари по дырам, достаточно прислать скриншот или mermaid или plantUML

## Домашка

В [lab/](lab/README.md) лежит намеренно дырявый магазин на Python. Он предоставляет HTTP API, хранит учебные профили и заказы, читает файлы и исполняет решения AI-помощника. Все данные синтетические.

**Задача**: с помощью агента найти все дыры, сделать репорт 2, исправить дыры, написать промпт для судьи, сделать репорт 2, открыть PR

В Ubuntu WSL из `practices/practice_06`:

```bash
make install
make step6
make test
make run
```

`step6` запускает отдельный свой процесс магазина и повторяет 24 HTTP security
checks; `test` — 61 тест, включая неизменённые 16 исходных. `sandbox.py` не менялся.
В исходном Makefile цели step6 не было; она добавлена согласно критериям задания.

Модельные эксперименты выполнялись в Windows PowerShell, отдельно от WSL make.
OpenCode 2.0.18 здесь не поддерживает указанный в учебном примере `run --dir`:
эквивалент — перейти в `practices/practice_06` и выполнить `run --standalone`.
Автоматизация точных входов/выходов из корня репозитория:

```powershell
python practices/practice_06/lab/model_experiment.py --phase after
```

Используется запущенная локальная Ollama с `qwen3.5:4b`. У shop-planner и
threat-judge инструменты запрещены. Ответы сохраняются без внутренних рассуждений;
неверные инструменты/JSON не исправляются за модель. Архив before защищён от
случайной перезаписи уже исправленным сервисом; исходные эксперименты выполнены
до изменения service.py. Запуск after намеренно обновляет after-доказательства.

Повтор судьи (из корня, установленная Ollama/OpenCode):

```powershell
ollama create itmo-practice06-judge -f practices/practice_06/Modelfile.judge
python practices/practice_06/lab/judge_review.py
```

Это локальный профиль на уже скачанных Qwen-весах с 16K контекстом для judge,
а не замена модели в основном сравнении shop-planner до/после. Судья может
ошибаться и нарушать требуемый формат: читать исходный ответ и JUDGE_REVIEW.md.
Проверки проходят на реальном HTTP; все адреса и fixtures учебные.
