# Дай почитать

Локальный сервис обмена бумажными книгами. Условия и критерии практики 8 лежат в [README практики](README.md). Стартовая версия проекта взята из коммита `a2a4644` после проверки автоисправления в 7.2.

## Запуск на Windows

Откройте PowerShell в папке `practices/practice_08` и выполните команды.

```powershell
python -m venv .venv
python -m pip --python .venv install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

Откройте http://127.0.0.1:8000. После отправки формы регистрации откройте последний файл в папке `mail/` и перейдите по ссылке из письма. На странице активации задайте публичное имя и пароль. Для проверки обмена используйте два аккаунта, например в разных профилях браузера.

```powershell
.\.venv\Scripts\python.exe manage.py test
```

## Сценарий для практики 8

Читатель ищет книгу в каталоге, открывает карточку, выбирает одну из своих книг и отправляет предложение владельцу. После отправки читатель видит созданный обмен и своё сообщение. Сценарий использует существующие страницы Django и сохранение обмена в базе данных.

Для макета нужны каталог, карточка и форма предложения. Покажем, как выглядят пустые результаты поиска, отсутствие подходящей книги для обмена, ожидание ответа сервера, ошибка формы и успешно созданное предложение. Демо пройдёт с двумя тестовыми аккаунтами, у каждого будет минимум одна опубликованная книга.

Клиентские тесты проверят видимый результат, работу с клавиатуры, обязательные поля, пустую выдачу, задержку и ошибку сервера. Отдельная проверка зафиксирует, что повторный Enter или двойной клик во время ожидания создаёт один запрос. Автоматические проверки состояний будут подменять ответы сервера, а демонстрационный прогон пройдёт через Django и тестовую базу.

Для сдачи сохраним макет, команды запуска, скриншоты состояний, результаты тестов и краткую запись о том, какие варианты предложил AI и что поменялось после проверки.

## Как проходит обмен

1. Каждый участник выставляет книгу с фото состояния и указывает, что готов принять взамен. В каталоге можно искать по названию или автору и по тексту пожеланий. Эти фильтры можно сочетать.
2. Один участник выбирает свою книгу и отправляет предложение с сообщением. Второй получает предложение в разделе «Обмены». Переписку видят только они.
3. После принятия обе книги резервируются, а конкурирующие предложения закрываются. Участники договариваются о встрече и сверяют состояние книг с фотографиями.
4. Каждый отдельно отмечает получение. Только после двух отметок обмен попадает в публичную историю. В профиле видны факт подтверждения почты и число завершённых обменов.
5. Пока получение не отмечено, отмена согласованного обмена требует согласия обоих. При споре сохраняются переписка и резерв. Если участники урегулировали спор, они могут подтвердить получение или согласовать отмену, когда ни один ещё не подтвердил получение.

Подтверждённая почта и история помогают оценить надёжность участника. Физическое получение сервис самостоятельно проверить не может. Для будущего обмена с доставкой стоит отдельно хранить статусы и идентификаторы отправлений по каждой стороне и предусмотреть разбор споров.

## Настройки

Локальный проект использует SQLite, почту в файлах, постоянный секрет из `.local-secret` и загруженные фото из `media/`. Пароли хэширует Django. Ссылка активации действует сутки, пароль задаётся после открытия ссылки, адреса почты не показываются в профилях. Фото ограничены по размеру и перекодируются в JPEG. Формы защищены CSRF. Ограничение скорости входа и регистрации использует локальный кэш.

Для размещения настройте `BOOKSHARE_DEBUG=0`, `BOOKSHARE_SECRET_KEY`, `BOOKSHARE_PUBLIC_URL` (HTTPS), `BOOKSHARE_SMTP_HOST`, `BOOKSHARE_SMTP_PORT`, `BOOKSHARE_SMTP_USER`, `BOOKSHARE_SMTP_PASSWORD` и `BOOKSHARE_FROM_EMAIL`. Настройте HTTPS, раздачу статики и фото, лимит тела запроса и общий лимит запросов на прокси. В режиме разработки письма сохраняются локально, в режиме размещения отправляются по SMTP.
