# Команда логики — уточнённая спецификация

Статус: контракт согласован пользователем в чате 2026-10-30;
команда логики независимо сверила спецификацию с UI до реализации.
Источник HTTP и сообщений: [общий контракт](contract.md).

## User story LOGIC-1

Как пользователь панели, я хочу получить то же поведение Registry через HTTP.

- Given один экземпляр Registry, When получен GET /, Then HTML использует
  отсортированный names(), не внутреннее множество.
- Given валидная форма подписки, When вызван subscribe, Then True/False
  преобразуется в соответствующий код сообщения и перенаправление 303.
- Given форма отписки, When вызван unsubscribe, Then True/False также
  преобразуется в нормальный результат; прочие имена сохраняются.
- Given пустое/длинное имя, When Registry отклоняет ввод, Then HTTP 400
  показывает ошибку, состояние реестра не меняется.
- Given некорректная форма, When не выполнены условия HTTP-контракта,
  Then ошибка возвращается до вызова Registry.

Использовать однопоточный HTTPServer: обработка запросов последовательна,
дополнительная синхронизация Registry не нужна. Не менять его исключения
и публичные методы. Серверная проверка отвечает за корректность ввода.

## Уточнения на границе UI и логики

- Передавать исходное значение name в публичный метод Registry: strip и
  проверка 80 Unicode-символов остаются ответственностью существующего кода.
- При корректной форме, отклонённой Registry, возвращать введённое name в UI
  для исправления. При отсутствующем, повторяющемся, лишнем или недекодируемом
  поле возвращать 400 с пустым полем: единственного исходного имени нет.
- Успешные операции, включая False, используют только фиксированные коды
  результата в перенаправлении; UI переводит их в четыре сообщения контракта.
  Неизвестный код не отображается как пользовательский текст.
- Проверить Content-Length и предел 4096 байт до чтения/разбора формы.
  Пустое значение name не терять при разборе: это ошибка имени, а не отсутствие
  поля. Некорректный UTF-8 отклонять вместо замены символов.
- Кодировка HTML-ответов и формы — UTF-8; длина ответа задаётся в байтах.

## Изменения относительно исходной версии

Определены HTTP-адаптер, однопроцессное состояние, обработка False,
перевод ошибок в HTML и отсутствие долговременного хранения.
