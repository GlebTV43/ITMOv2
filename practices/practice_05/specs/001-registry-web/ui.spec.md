# Команда UI — уточнённая спецификация

Статус: общий контракт согласован пользователем 2026-10-30; UI-спецификация
проверена отдельной командой UI до реализации.
Источник API, ошибок и данных: [общий контракт](contract.md).

## User story UI-1

Как пользователь, я хочу управлять подписчиками на одной странице.

- Given пустой реестр, When открыта /, Then видны пустое состояние,
  подписанная метка поля имени и кнопка «Подписать».
- Given введено `  Анна  `, When отправлена форма, Then после 303 видны
  `Анна` и сообщение об успешной подписке.
- Given существующее имя, When повторно подписываем его, Then виден
  нормальный результат «Уже подписан», список не дублируется.
- Given строка списка, When нажата её кнопка «Отписать», Then удаляется
  соответствующее имя и отображается результат операции.
- Given имя уже отсутствует, When повторно отправлена его форма отписки,
  Then после 303 показано «Подписчик не найден» без ошибки и изменения списка.
- Given неверное имя, When отправлена форма, Then показана ошибка,
  введённое значение сохранено, список не изменён.

Имена экранируются в тексте и скрытом поле формы отписки. Порядок задаёт
логика, UI его не пересортировывает. Формы работают без JavaScript.
Длина HTML-поля не блокирует допустимое имя с пробелами вокруг:
авторитетная проверка длины выполняется после strip на сервере.
Форма отправляет поле `name` в UTF-8 без преобразования имени на клиенте.
Для неверного имени сохраняется исходное значение единственного корректно
разобранного поля. Для повреждённого тела или неоднозначных полей имя
не восстанавливается: интерфейс показывает общую ошибку формы и текущий список.

## Изменения относительно исходной версии

Выбраны серверные формы вместо неопределённого API. Зафиксированы 303,
нормальные исходы дубля/отсутствия, ошибки, ограничения тела и время жизни.
Отдельный loading-state не нужен для синхронной навигации браузера.
