# Unit-проверки

| Требование или правило | Что проверяем изолированно | Вход | Ожидаемый результат | Подтверждение |
|---|---|---|---|---|
| `diff` обязателен | валидация входной модели | `{}` | контролируемая ошибка валидации, а не `KeyError` | U-01, unit test input schema |
| `diff` должен быть строкой | тип поля | `{"diff": 123}` | запрос отклонён до вызова LLM | U-02 |
| Не более трёх рисков | валидатор результата | 4 риска от mock LLM | результат отклонён или сокращён по заданному правилу | U-03 |
| Для риска нужно доказательство | валидатор структуры | риск без file/location/evidence | риск помечен как неполный или не проходит validation | U-04 |
| AI не принимает решение по PR | шаблон prompt/result schema | mock-ответ с `APPROVE` как действием | система не выполняет внешнее действие; текст остаётся только черновиком | U-05 |
| Пустой diff не несёт полезного контекста | input validation | `{"diff": ""}` | контролируемая ошибка 4xx или явный отказ до LLM | U-06 |

Минимальный набор можно реализовать через unit-тесты входной схемы, Prompt Builder и Result Validator с mock LLM, без сетевых вызовов.

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): `P1-09`.
- Что проверил студент и какие исправления поручил агенту: тесты привязаны к конкретным правилам Context Pack; убраны проверки, требующие реального LLM в unit-слое.
