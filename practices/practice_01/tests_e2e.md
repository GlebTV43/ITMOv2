# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Подтверждение |
|---|---|---|---|---|
| Позитивный | сервис запущен; доступен fake/stub LLM; есть `TRAINING_PR.diff` | ревьюер отправляет diff в POST `/api/reviews` | получает summary, ≤3 рисков и checks; ни одно действие по PR не выполнено автоматически | E2E-01 |
| Негативный | сервис запущен | отправить `{}` вместо diff | пользователь получает понятную 4xx-ошибку; процесс сервиса продолжает работать | E2E-02 |
| Граничный | установлен лимит размера diff | отправить diff на границе лимита и на 1 байт больше | допустимый проходит, превышающий лимит отклоняется до LLM | E2E-03 |

Для учебной практики E2E проверяет пользовательский путь от HTTP-входа до черновика ответа. Реальные GitHub approve/merge намеренно отсутствуют в сценарии.

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): `P1-12`.
- Что проверил студент и какие исправления поручил агенту: оставил только сквозные пользовательские сценарии, исключил дублирование unit-проверок и любые автоматические действия в GitHub.
