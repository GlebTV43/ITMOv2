# Tree of Thoughts

- **Инструмент / модель:** gpt-5.6 Sol
- **Решение, для которого нужны альтернативы:** как строить нагрузочное тестирование сервиса, если внешний LLM-провайдер ещё не выбран.
- **Критерии выбора:** воспроизводимость, реалистичность, независимость CI, стоимость и возможность объяснить источник результата.

## Запрос

```text
Предложи три различимые стратегии load testing для AI review service при неизвестном production LLM.
Не раскрывай скрытые рассуждения: дай только итоговые альтернативы, плюсы/минусы и оценку по критериям.
После сравнения выбери вариант, который можно воспроизводимо проверять сейчас и расширить после выбора provider.
```

## Варианты решения

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A. Только real LLM | максимальная близость к реальной цепочке | нестабильная latency, квоты, стоимость, сеть; provider ещё неизвестен | реалистичность высокая, воспроизводимость и доступность сейчас низкие |
| B. Только fake LLM | детерминированно, дёшево, подходит CI | не измеряет квоты, 429 и реальную provider latency | воспроизводимость высокая, provider-реалистичность низкая |
| C. Два слоя: fake сейчас + provider позже | CI остаётся стабильным, а provider можно добавить отдельным профилем после появления требований | нужно поддерживать два профиля и не смешивать их выводы | лучший баланс по всем заданным критериям |

## Выбор

- **Выбранная альтернатива:** C — два слоя.
- **Почему:** она проверяет нашу обвязку уже сейчас и не заставляет придумывать модель/SLA. Позже можно добавить отдельный real-provider профиль, не меняя смысл CI-проверок.
- **Как проверим:** основной план должен содержать L-01…L-04 с fake LLM и отдельный L-05 со статусом `blocked` до появления подтверждённых provider-параметров.

## Что изменили в исходном артефакте

- **Файл и раздел:** [`tests_load.md` → «Порядок выполнения»](../../practice_01/tests_load.md#порядок-выполнения).
- **Изменение:** зафиксирован двухслойный порядок: детерминированный fake LLM сейчас, внешний provider после разблокировки требований.
- **Что отклонили:** A как единственную стратегию из-за невоспроизводимости и B как единственную стратегию из-за отсутствия проверки реального provider.
