# Few-shot

- **Инструмент / модель:** gpt-5.6 Sol
- **Артефакт Практики 1:** [`../../practice_01/tests_load.md`](../../practice_01/tests_load.md)
- **Что хотим улучшить:** сделать каждый нагрузочный сценарий проверяемым и не смешивать учебные параметры с production SLA.

## Примеры

### Хороший результат

```text
Цель: проверить, что слишком большой diff отклоняется до обращения к LLM.
Нагрузка: 30 запросов с размером MAX_DIFF_BYTES + 1.
Метрики: HTTP status и число вызовов fake LLM.
Критерий: 100% запросов дают контролируемый 4xx, llm_calls = 0.
Источник: ADR требует input validation; конкретное значение MAX_DIFF_BYTES берётся только из конфигурации.
```

Почему пример хороший: есть одна проверяемая цель, понятный стенд, наблюдаемый результат и указано, откуда берётся лимит.

### Плохой результат

```text
Сервис должен выдерживать 500 RPS, а p95 всегда должен быть меньше 100 мс.
Нужно убедиться, что LLM не тормозит.
```

Почему пример плохой: числа не подтверждены источником, не описан стенд и смешана производительность нашей API-обвязки с внешней LLM.

## Запрос

```text
Перепиши сценарии tests_load.md по образцу хорошего примера.
Для каждого сценария укажи цель, нагрузку, измеряемые метрики, проверяемый критерий и источник требования.
Не копируй значения из плохого примера и не придумывай production SLA.
Если параметр проекта неизвестен, пометь сценарий blocked до появления подтверждённого значения.
```

## Что получили

Модель предложила единый формат сценариев и отдельно выделила три класса проверок: baseline API с fake LLM, проверки защитных лимитов и будущий тест реального провайдера. Вместо безусловного production-порога для неизвестного `MAX_DIFF_BYTES` появился сценарий с `MAX_DIFF_BYTES + 1`, который активируется только после появления реальной настройки.

## Что изменили в исходном артефакте

- **Файл и раздел:** [`tests_load.md` → «Сценарии»](../../practice_01/tests_load.md#сценарии).
- **Изменение:** таблица приведена к структуре хорошего примера; добавлены ID L-01…L-05, источник и статус для неизвестных параметров.
- **Как проверили:** у каждой строки вручную проверены цель, нагрузка, метрика, критерий и источник.
- **Что отклонили:** любые фиксированные production RPS/latency без подтверждённого требования.
