# Практика 04: две фичи и среда агента

Материалы задания взяты из `ai-course-avito/ITMOv2`, commit `87133163e23037f850ea2858955f021d23fcedf9`. Исходные `../README.md`, `../presentation.pdf` и `../presentation.pptx` сохранены без изменений. Работа выполнена в отдельном учебном проекте, что разрешено условием.

## Результат

Сервис `Registry` хранит подписчиков в памяти. Фича A проверяет тип имени, удаляет пробелы по краям, отклоняет пустое имя и имя длиннее 80 символов до изменения состояния. Повторная подписка после нормализации возвращает `False`. Фича B удаляет подписчика с той же валидацией: возвращает `True` при удалении и `False`, если имени нет. Повторная отписка безопасна; другие подписчики сохраняются.

Объединённый результат: **56 тестов проходят**, автоматизация skill проверяет **21 сценарий**, отдельный MCP-клиент проверяет **12 сценариев**. Сохранены реальные события загрузки skill, вызовов MCP, автоматических FAIL/PASS и отдельного ревью. Новая сессия восстановила состояние по handoff и проверила проект без правок.

Конфигурация провайдера использует поддерживаемую миграцию поля `provider`: проверенный вариант с `providers` был отброшен установленной версией. Для MCP применяется `mcp.servers`, обязательный `type: local` и `environment.PYTHONIOENCODING=utf-8`. Ключи в репозитории отсутствуют; используются сохранённая учётная запись OpenCode или переменная `VSELLM_API_KEY`.

### Устройство созданного skill

Skill `subscription-contract` предназначен для этого сервиса: он задаёт порядок работы с контрактом, reference и MCP, затем требует увидеть падающую проверку перед исправлением. Его содержательная автоматизация — `scripts/probe.py`: скрипт действительно вызывает публичные методы `Registry`, проверяет границы длины, нормализацию, дубликаты, отсутствие изменения состояния при отказе и сценарии отписки. Он сохраняет JSON по каждому случаю и завершает работу с ненулевым кодом при нарушении. При исходном сервисе прошёл только 1 из 9 случаев; после A прошли 9/9, после B — 21/21.

Снимки: [исходный FAIL](results/skill_probe_baseline.json), [A](results/skill_probe_a.json), [A+B](results/skill_probe.json). Reference и probe входят в материалы сдачи; их назначение и пути указаны в skill.

### Собственный MCP: успех и ошибка

Tool `inspect_subscriber` независимо проверяет вход по контракту, не вызывает реализацию `Registry` и не изменяет подписчиков.

| Вход | Фактический результат OpenCode |
|---|---|
| `"  Ann  "` | `{"normalized":"Ann","length":3,"valid":true}` |
| `"   "` | Ошибка tool: `ValueError`, имя пустое после удаления пробелов |
| 80 букв `a` | Успех, длина 80 |
| 81 буква `a` | Ошибка tool: `ValueError`, превышен максимум 80 |

В одном вызове был передан **строковый** `"42"`, поэтому он корректно принят. Это не доказывает автоматическое преобразование чисел клиентом. Настоящее числовое `42` проверено через stdio-клиент и тест: сервер возвращает `isError: true` с `TypeError`. Часть прежних пояснений агента в сырых журналах ошибочно предполагала преобразование; здесь приведено уточнение по фактическим типам входа.

Дополнительно исправлен обнаруженный сбой на JSON `null`: вместо завершения процесса сервер возвращает JSON-RPC ошибку и продолжает обрабатывать `ping`. Проверены неверные envelopes, параметры и arguments, malformed JSON, неизвестные method/tool и Unicode. Подтверждения: [mcp_stdio.json](results/mcp_stdio.json), [test_mcp.py](tests/test_mcp.py). Сервер реализует необходимый набор `initialize`, notification initialized, `tools/list`, `tools/call`, `ping`; это учебная реализация, а не полный MCP SDK.

## Как воспроизвести и показать ревьюеру

Из PowerShell, в каталоге `practices/practice_04/lab`:

```powershell
python scripts/check.py
python scripts/probe.py
python scripts/mcp_demo.py
opencode mcp list
opencode run --standalone --auto --model vsellm/anthropic/claude-sonnet-4.6 "Прочитай AGENTS.md. Загрузи subscription-contract. Вызови inspect_subscriber для имени '  Ann  ' и для пустого имени. Ничего не изменяй."
```

Обычный запуск `opencode run --standalone ...` проверен без служебного скрипта координатора; сохранённая учётная запись доступна. В другом окружении нужно подключить собственный VseLLM аккаунт или задать `VSELLM_API_KEY`, установить OpenCode и Python. `check.sh` доступен для bash; Windows-команда runner — `python scripts/check.py`.

Для показа hook можно в отдельной демонстрационной ветке поручить агенту добавить падающий тест, увидеть `[AUTOCHECK FAIL]`, затем выполнить исправление и увидеть PASS. Уже выполненные циклы A и B доступны в журнале, поэтому для просмотра доказательств повторно менять код не требуется.

## Ограничения и авторство

Данные не сохраняются между процессами; потокобезопасность, HTTP и база данных вне выбранного контракта. Cloud API используется рабочей моделью, а проект, MCP и тесты исполняются локально. Hook реагирует на завершённые OpenCode `write`, `edit`, `apply_patch`; shell-команды и внешние редакторы требуют ручного запуска runner. Правила папки в AGENTS являются инструкциями агенту, а не изоляцией ОС; конфигурация разрешает инструменты для неинтерактивного учебного запуска.

Код и первичные документы созданы OpenCode; координатор проверил их, исправил выявленные дефекты конфигурации и протокола, уточнил документы, организовал Git/worktree и публикацию. Отдельный review был чтением кода; запуск тестов выполнен рабочим агентом и координатором. [reflection.md](reflection.md) описывает наблюдения этой работы. Живое объяснение и обсуждение с человеком-ревьюером ещё не проводились; их выполняет студент.
